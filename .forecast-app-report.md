## Architecture note (important deviation from the brief)

The workspace's package proxies were degraded during this build and forced two
substitutions, both fully working and verified:

1. **Backend transport.** The brief specified `databricks-sql-connector` + FastAPI.
   The Apps build pypi proxy intermittently timed out on wheels of every size/version
   (numpy, pydantic-core, cryptography, and even tiny ones like certifi/click — it also
   hadn't mirrored the newest 2026 releases). To make deploy reliable, the backend was
   reduced to **zero pip dependencies**: it uses only the Python standard library
   (`http.server` + `urllib`). SQL runs through the **SQL Statement Execution REST API**
   (`POST /api/2.0/sql/statements`) on the same warehouse with fully parameterized
   named (`:name`) statement parameters — same read-only, parameterized-SQL contract the
   brief intended, just via REST instead of the connector.
2. **Frontend chart.** The internal npm proxy only mirrors canary React-ecosystem builds
   (no stable react/react-dom/scheduler/react-is; registry.npmjs.org returns 503), so
   Recharts' stable transitive deps were unavailable. React is pinned to a self-consistent
   canary trio (`19.3.0-canary-ff7445e6-20260831`) and the forecast chart is a
   **dependency-free inline SVG** (coral improved line, navy baseline line, shaded
   prediction band, legend, hover tooltip) — meeting the spec visually.

## Auth / DB idiom used

- Token: remote = OAuth client-credentials (`grant_type=client_credentials&scope=all-apis`,
  HTTP Basic client_id:client_secret) → all-apis bearer; local = SDK
  `w.config.authenticate()` from the `field-eng-east` profile. Cached until ~60s before
  expiry. `IS_DATABRICKS_APP` (DATABRICKS_APP_NAME) selects the path; DATABRICKS_HOST is
  normalized to include `https://`.
- SQL: `POST {host}/api/2.0/sql/statements` with `warehouse_id`, `statement`,
  `parameters` (named, typed), `disposition=INLINE`, `format=JSON_ARRAY`, `wait_timeout=50s`;
  poll `GET /api/2.0/sql/statements/{id}` if not inline. Rows built from
  `manifest.schema.columns` + `result.data_array`, cells coerced by column type
  (INT/LONG→int, DOUBLE→float, DATE/TIMESTAMP→ISO string). All user input parameterized.

## Transport / DB idiom

- **Transport:** `backend/main.py` is a FastAPI app. Routes `GET /api/health`,
  `GET /api/filters`, `GET /api/forecast`, `GET /api/adjustments`,
  `POST /api/adjustments` call the unchanged `backend/api.py` handlers; pydantic models
  type the POST body and all responses; error `(status, {"error":...})` tuples become
  `HTTPException`. The built SPA is mounted (`/assets` static + catch-all `/{full_path}`
  fallback to `index.html`, with a path-traversal guard and `api/*` 404 passthrough).
  Sync `def` handlers (the connector is synchronous; FastAPI runs them in a threadpool).
  `app.yaml` command is now `python -m uvicorn backend.main:app --host 0.0.0.0 --port 8000`.
- **DB:** `backend/db.py` `run_query(sql, params)` opens a short-lived
  `databricks.sql.connect(server_hostname=<host, no scheme>,
  http_path=/sql/1.0/warehouses/ec3c986a891e0b79, access_token=<dual-mode token>)`
  per query and binds the existing `:name` params via the connector's **native**
  parameter markers (`cursor.execute(sql, parameters=...)`) — SQL kept fully
  parameterized, `queries.py` unchanged. Cells arrive already typed; only
  date/datetime→ISO string and Decimal→float are normalized to match prior payloads.
- **Auth:** `backend/config.py` now uses the Databricks SDK for tokens in both modes
  (app: injected SP OAuth via `WorkspaceClient()`; local: `WorkspaceClient(profile=
  field-eng-east)`), `w.config.authenticate()` → bearer. `server.py` and `httpjson.py`
  were removed; `api.py`, `queries.py`, `tests/` kept (tests unchanged — they monkeypatch
  `queries.run_query`).
